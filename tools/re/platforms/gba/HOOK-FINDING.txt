=== WHY EXEC HOOKS (FOOTSTEPS) CANNOT WORK: ARCHITECTURAL, NOT A BUG IN THE SHIM ===

FROM mGBA'S OWN SOURCE (src/arm/debugger/debugger.c, src/debugger/debugger.c):

  * WATCHPOINTS install a MEMORY SHIM (ARMDebuggerInstallMemoryShim) directly into the ARM
    memory layer, so they fire on memory ACCESS regardless of who drives execution.

  * EXECUTE BREAKPOINTS do not. They are checked ONLY from mDebuggerRunTimeout's loop:

        case DEBUGGER_RUNNING:
            if (!hasBreakpoints(...)) core->runLoop(core);
            else { core->step(core); platform->checkBreakpoints(platform); }

    That is the DEBUGGER's run loop. A Lua script calling `emu:runFrame()` drives frames
    through the core's own path, never the debugger's stepping loop. So an exec breakpoint is
    installed, is counted by hasBreakpoints(), and is then NEVER CHECKED.
    => measured exactly that: installed, 0 fires.

MEASURED HOOK BEHAVIOUR ON mGBA 0.11 (dev), LIVE FireRed:

  setBreakpoint(pc, segment=-1)                      INSTALLED, 0 fires / 60 frames
  setRangeWatchpoint(type=0 WRITE)     0x040000DC    INSTALLED, FIRES          <- in production
  setRangeWatchpoint(type=1 READ)                   INSTALL FAILS (pcall false)
  setRangeWatchpoint(type=2 READWRITE) 0x040000DC    INSTALLED, fires once
  setRangeWatchpoint(type=2) 0x0800016C / 0x08000000 / 0x02000000   INSTALLED, 0 fires

  (READ-ONLY WATCHPOINTS DO NOT INSTALL AT ALL on this build. READWRITE installs and fires on
   IO/VRAM, but not on the RAM/ROM addresses tried.)

WHAT THIS MEANS FOR THE PORT:

  * `memory.registerwrite` -> REAL write watchpoint. IMPLEMENTED AND VERIFIED
    (`registerwrite(0x40000DC) -> REAL watchpoint id=1`), live narration unaffected.
  * `memory.registerexec` (footsteps, and the VRAM-DMA cpu_set/cpu_fast_set hooks) -> CANNOT be
    reimplemented on this build by any mechanism tested:
        - frame-polling the PC : 0 hits from 38 hooks (ROM code unreachable from a frame poll)
        - exec breakpoints     : wrong subsystem, never checked under script-driven frames
        - read watchpoint      : read-only does not install; readwrite installed but 0 fires
    Footsteps therefore DO NOT WORK in mGBA 0.10.5/0.11 via this shim. This is a real,
    measured limitation, not an unverified suspicion.

  * POSSIBLE FUTURE ROUTES (untested, do not assume they work):
        - drive frames through the DEBUGGER's run path rather than `emu:runFrame()`
        - fix the segment argument for execute breakpoints (ARM=0 / THUMB=1?) and re-test with
          the debugger's run loop actually engaged
        - reimplement footstep detection WITHOUT registerexec: poll the observable effect (map
          bank byte + a position change) instead of the PC. This is the most promising route and
          needs no debugger at all.

=== readRegister RETURN TYPE IS BUILD-DEPENDENT ===
0.10.2 docs: string | 0.11 dev docs: wrapper | INSTALLED 0.11 MEASURED: NUMBER
(pc -> 134219948, r2 -> 50344176; all coercions confirmed numeric)
=> decodeRegister must pass numbers through and only translate byte strings. It does.
