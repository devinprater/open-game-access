==============================================================================
Notes on the raw output above
==============================================================================

- The GET_MEMORY_MAP replies for the four readable cores begin directly with a
  region, not with the command name; the five failures begin with the command
  name followed by ERROR. That is why the failures are one-liners and the
  successes are long tab-separated lines.

- RUN_FRAMES 300 answered "RUN_FRAMES 300"; RUN_FRAMES 900 answered
  "The command did not answer in time." The server gives a deferred command ten
  seconds.

- The stdio transport (--mcp-stdio) answered initialize, ping and tools/call, but
  tools/list answered nothing and wedged the session; every later tools/call on
  it also went unanswered. HTTP returned 200 with 23,277 bytes and 80 tools for
  the same call.

- The config that produced the successful runs (minimal, hand-written):

    mcp_server_enable = "true"
    mcp_server_port = "54123"
    mcp_server_bind_address = "127.0.0.1"
    mcp_server_token = "..."
    pause_nonactive = "false"

  Default port 55357 fails on this machine: Windows reserves 55357-55456
  (Hyper-V/WSL), so the server logs "[MCP] Could not listen on
  127.0.0.1:55357" and never listens.
